# 认证与无感续期

## 接口

| 方法 | 路径 | 请求 | 作用 |
| --- | --- | --- | --- |
| `POST` | `/users` | `{ "name", "email", "password" }` | 注册，密码 8–128 位，包含字母、数字和符号，不含空格 |
| `POST` | `/auth/login` | `{ "email", "password" }` | 登录并领取访问令牌 |
| `POST` | `/auth/refresh` | 刷新令牌 Cookie | 轮换刷新令牌并领取新访问令牌 |
| `GET` | `/auth/me` | `Authorization: Bearer <token>` | 获取当前用户 |
| `POST` | `/auth/change-password` | Bearer 令牌与 `{ "oldPassword", "newPassword" }` | 新密码遵循同一复杂度规则；成功后撤销所有会话 |
| `POST` | `/auth/logout` | 刷新令牌 Cookie | 退出登录并撤销该会话 |

用户列表需登录：普通用户的 `GET /users` 只返回本人，超级管理员可查询所有用户。`GET /users/:id` 允许本人或超级管理员查看；`PATCH/DELETE /users/:id` 仍仅允许账号本人操作。`PATCH /users/:id` 只能修改名称或邮箱，密码必须通过 `/auth/change-password` 修改。

同一邮箱在 15 分钟内连续输错密码 10 次后，后续登录请求返回 `429`，锁定 15 分钟。成功登录会清除失败计数；大小写不同的同一邮箱共用计数。计数保存在数据库中，重启服务后仍有效。

所有注册用户和迁移前的用户默认是 `user`。注册请求不能设置 `role`；超级管理员角色只由数据库管理员在核对目标 UUID 后授予，例如：

```sql
SELECT id, email, role FROM users WHERE id = '<已核对的用户UUID>';
UPDATE users SET role = 'super_admin'
WHERE id = '<已核对的用户UUID>' AND password_hash IS NOT NULL;
```

撤销时将 `role` 改回 `user`。单独启动 API 时不会自动产生超级管理员账号；仓库根目录的一键演示会通过 `seed` 服务创建演示管理员。

## 本地调用示例

开发服务只监听 `127.0.0.1`，下面的 HTTP 地址仅用于本机学习。生产环境必须配置 HTTPS。`curl` 的 `-c` 将 HttpOnly Cookie 保存到文件，`-b` 在下次请求中带上它。

```bash
# 1. 注册
curl -i -X POST http://127.0.0.1:3000/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"Alice","email":"alice@example.com","password":"A-long-password-123"}'

# 2. 登录。将 Results.accessToken 复制为下面的 <ACCESS_TOKEN>
curl -i -c /tmp/nest-learning-cookies.txt \
  -X POST http://127.0.0.1:3000/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"alice@example.com","password":"A-long-password-123"}'

# 3. 带访问令牌调用接口
curl -i http://127.0.0.1:3000/auth/me \
  -H 'Authorization: Bearer <ACCESS_TOKEN>'

# 4. 访问令牌即将过期时刷新。复制新的 Results.accessToken
curl -i -b /tmp/nest-learning-cookies.txt \
  -c /tmp/nest-learning-cookies.txt \
  -X POST http://127.0.0.1:3000/auth/refresh

# 5. 修改密码后，当前及其他会话都失效，需要重新登录
curl -i -X POST http://127.0.0.1:3000/auth/change-password \
  -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  -H 'Content-Type: application/json' \
  -d '{"oldPassword":"A-long-password-123","newPassword":"A-different-password-456"}'

# 6. 退出登录（使用登录或刷新后最新的 Cookie）
curl -i -b /tmp/nest-learning-cookies.txt \
  -X POST http://127.0.0.1:3000/auth/logout
```

登录和刷新接口的 `Results` 包含 `accessToken`、`tokenType: "Bearer"`、`expiresIn: 900`（秒）和 `user`；刷新令牌只通过 `Set-Cookie` 传递，不在 JSON 中返回。

## 前端无感续期流程

1. 登录成功后，把访问令牌保存在应用内存中；浏览器自动保存 HttpOnly 刷新 Cookie。调用 `fetch` 时使用 `credentials: 'include'`。
2. 页面重新打开时调用一次 `POST /auth/refresh`，从响应中取得新访问令牌。这样不需要再次输入密码。
3. 在访问令牌过期前约 30 秒调用刷新接口，或在受保护请求收到 `401` 时刷新并重试一次。并发请求要共用同一个刷新 Promise，避免旧 Cookie 被并发轮换。
4. 刷新接口返回 `401` 时跳转登录页。修改密码或退出登录后，清除内存中的访问令牌。

访问令牌有效期为 15 分钟，刷新令牌有效期为 7 天；每次刷新都会替换两种令牌并立即使旧令牌失效。刷新令牌 Cookie 设置为 `HttpOnly`、`SameSite=Strict`，生产环境还设置 `Secure`。不要将令牌写入浏览器 `localStorage` 或 `sessionStorage`。

## 密码、旧账号和传输

- 数据库只保存使用随机盐和 scrypt 生成的密码哈希，不保存明文密码；用户接口响应不会包含密码或哈希。
- 迁移前创建的用户没有密码哈希，按当前约定暂时不能登录。不能在没有身份验证的情况下为这些账号自动设置密码。
- 哈希解决数据库存储问题，**不会加密网络传输**。生产环境设置 `NODE_ENV=production`、`HTTPS_KEY_PATH` 和 `HTTPS_CERT_PATH`，服务会使用 HTTPS 启动；缺少证书时拒绝启动。生产环境的 Cookie 使用 `Secure`，响应包含 HSTS。
- 本地开发模式只监听 `127.0.0.1`。不要把开发 HTTP 服务暴露到公网或局域网。

实现依据：[OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP 会话管理建议](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[OWASP 刷新令牌轮换建议](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html)。
