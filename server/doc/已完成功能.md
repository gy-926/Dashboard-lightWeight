# 已完成功能

本文记录 `Dashboard-lightWeight-Api` 内置 Nest API 已经实现的功能，以现有代码为准。

登录、修改密码和无感续期的完整调用流程见 [认证与无感续期](认证与无感续期.md)。

## 1. 项目基础

- `GET /` 返回学习项目的欢迎信息，包括 `message` 和 `author`。
- 使用 NestJS 的 Module、Controller、Service 分层：Controller 接收 HTTP 请求，Service 处理业务与数据访问。
- 通过环境变量配置 MySQL 连接，使用 TypeORM 管理 `users` 表。应用启动时关闭了自动同步表结构，表结构通过迁移维护。
- 用户主键为 UUID；`name` 最长 100 字符，`email` 最长 255 字符且在数据库中唯一。每条用户记录还包含自动维护的 `createdAt`、`updatedAt`。

## 2. 用户接口

| 方法 | 路径 | 功能 | 成功状态码 |
| --- | --- | --- | --- |
| `POST` | `/users` | 注册用户（需密码） | `201` |
| `GET` | `/users` | 普通用户仅查询自己；超级管理员可搜索、分页和排序查询全部用户 | `200` |
| `GET` | `/users/:id` | 本人或超级管理员按 UUID 获取用户 | `200` |
| `PATCH` | `/users/:id` | 部分更新用户 | `200` |
| `DELETE` | `/users/:id` | 删除用户 | `200` |

认证接口包括 `POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET /auth/me` 和 `POST /auth/change-password`。密码只保存带盐的 scrypt 哈希；访问令牌为 15 分钟，刷新令牌为 7 天，并在每次刷新时轮换。

文件接口包括 `POST /files`、`GET /files`、`GET /files/:id/download` 和 `DELETE /files/:id`。文件默认私有，普通用户只能操作本人文件，超级管理员可查看和操作全部文件。完整调用方式见 [文件存储.md](./文件存储.md)。

注册时，`name` 必须是非空字符串，`email` 必须符合邮箱格式，`password` 长度为 8–128 个字符，且包含字母、数字和符号，不含空格。更新接口可只提交 `name` 或 `email`。创建或更新为已存在的邮箱时返回 `409 Conflict`。`GET /users` 及按 ID 查询、更新、删除均需访问令牌；普通用户只可读取、修改和删除本人，超级管理员可额外读取其他用户。路径中的 `id` 使用 `ParseUUIDPipe` 校验格式。

### 接口调用方式

先准备 MySQL，并按 `.env.example` 配置本地 `.env`。在项目根目录应用迁移并启动服务：

```bash
./node_modules/.bin/typeorm-ts-node-esm migration:run -d data-source.ts
npm run start:dev
```

以下示例使用仅监听本机回环地址的开发服务 `http://127.0.0.1:3000`；生产环境必须使用 HTTPS。请求体为 JSON 时需设置 `Content-Type: application/json`。

**查看首页**

```bash
curl -i http://127.0.0.1:3000/
```

**注册用户**：请求体必须包含 `name`、`email` 和 `password`。成功时返回 `201`，从响应的 `Results.id` 取得新用户 UUID。响应不会包含密码或密码哈希。

```bash
curl -i -X POST http://127.0.0.1:3000/users \
  -H 'Content-Type: application/json' \
  -d '{"name":"Alice","email":"alice@example.com","password":"A-long-password-123"}'
```

**查询用户列表**：先调用 `POST /auth/login`，把返回的 `Results.accessToken` 复制到下面的 `<ACCESS_TOKEN>`。所有查询参数均可省略；`curl -G --data-urlencode` 会正确编码查询参数。

```bash
curl -i -G http://127.0.0.1:3000/users \
  -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  --data-urlencode 'queryKeys=name,email' \
  --data-urlencode 'queryValue=alice' \
  --data-urlencode 'queryMode=fuzzy' \
  --data-urlencode 'sortBy=email' \
  --data-urlencode 'sortOrder=DESC' \
  --data-urlencode 'skip=0' \
  --data-urlencode 'take=20'
```

按创建时间查看最新用户：

```bash
curl -i -G http://127.0.0.1:3000/users \
  -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  --data-urlencode 'sortBy=createdAt' \
  --data-urlencode 'sortOrder=DESC' \
  --data-urlencode 'take=10'
```

精确匹配邮箱的示例：

```bash
curl -i -G http://127.0.0.1:3000/users \
  -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  --data-urlencode 'queryKeys=email' \
  --data-urlencode 'queryValue=alice@example.com' \
  --data-urlencode 'queryMode=exact'
```

**查询单个用户**：将 `<UUID>` 替换为创建用户时返回的 `Results.id`。

```bash
curl -i 'http://127.0.0.1:3000/users/<UUID>' \
  -H 'Authorization: Bearer <ACCESS_TOKEN>'
```

**更新用户**：可只提交 `name` 或 `email`；下面只更新名称。

```bash
curl -i -X PATCH 'http://127.0.0.1:3000/users/<UUID>' \
  -H 'Authorization: Bearer <ACCESS_TOKEN>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"Alice Chen"}'
```

**删除用户**：删除成功返回 `200`，响应中的 `Results` 为 `null`。

```bash
curl -i -X DELETE 'http://127.0.0.1:3000/users/<UUID>' \
  -H 'Authorization: Bearer <ACCESS_TOKEN>'
```

## 3. 用户列表查询

`GET /users` 支持以下可选参数：

| 参数 | 默认值 | 规则 |
| --- | --- | --- |
| `skip` | `0` | 跳过的记录数，必须是大于等于 0 的整数 |
| `take` | `10` | 本页记录数，必须是 1 到 100 的整数 |
| `queryKeys` | `name,email` | 搜索字段，可传 `name`、`email` 或用逗号分隔的多个字段 |
| `queryValue` | 无 | 搜索文本，最长 100 字符；去掉两端空格后为空时不执行搜索 |
| `queryMode` | `fuzzy` | `fuzzy` 模糊匹配；`exact` 精确匹配 |
| `sortBy` | `name` | 排序字段，只允许 `name`、`email` 或 `createdAt` |
| `sortOrder` | `ASC` | `ASC` 升序或 `DESC` 降序 |

多字段搜索使用 `OR` 连接。`fuzzy` 模式使用 SQL `LIKE`，在查询值两侧添加 `%`；`exact` 模式使用 `=`。查询值通过 SQL 参数绑定传入，搜索字段和排序字段均受 DTO 白名单限制。

列表先按指定字段和方向排序；值相同时再按 `id` 升序排序，使相同数据集上的分页顺序确定。普通用户的查询始终限定本人，超级管理员可查询全部用户。`Total` 表示在当前权限和搜索条件下的总记录数，`Results` 只包含当前页。

示例：

```http
GET /users?queryKeys=name,email&queryValue=alice&queryMode=fuzzy&sortBy=email&sortOrder=DESC&skip=0&take=20
```

## 4. 统一校验与响应

全局 `ValidationPipe` 会转换并校验 DTO 参数；未在 DTO 中声明的请求字段会被拒绝，返回 `400 Bad Request`。例如 `sortBy=password`、`take=101` 都无法通过校验。

成功响应由全局拦截器统一包装：

```json
{
  "status": 200,
  "message": "success",
  "Results": [{
    "id": "用户 UUID",
    "name": "Alice",
    "email": "alice@example.com",
    "role": "user",
    "createdAt": "2026-09-18T00:00:00.000Z",
    "updatedAt": "2026-09-18T00:00:00.000Z"
  }],
  "Total": 1
}
```

异常由全局过滤器统一包装，保留相应的 HTTP 状态码，并返回 `Results: null`、`Total: 0`。单条查询和创建、更新接口的 `Results` 是对象；删除接口的 `Results` 是 `null`。

## 5. 数据库迁移与测试

- 已有迁移负责创建 `users` 表、将早期的整数主键改为 UUID、增加时间列、密码哈希列、认证会话表、用户角色及失败登录计数表。旧用户无密码，暂时不能登录。
- Service 单元测试覆盖默认分页、模糊搜索、精确搜索和自定义排序；DTO 测试覆盖参数转换、默认值与非法参数。
- HTTP 端到端测试覆盖根路径、普通用户与超级管理员的查询权限、10 次失败登录限制、时间字段，以及密码哈希、登录、令牌轮换、修改密码和退出登录。
- 可用 `npm test`、`npm run test:e2e`、`npm run build`、`npm run lint` 进行验证。端到端测试需要可连接的本机 MySQL。
